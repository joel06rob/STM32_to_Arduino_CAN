# STM32 / Arduino CAN Project
## Overview
I built this in my process of learning Embedded Development. I had already learnt the theory of the CAN communication protocol, however I wanted to demonstrate my learning and develop a meaningful project. 

This project creates a standard, two-way CAN connection between the STM32F446RE Nucleo and the Arduino Uno Q by using two SN65HVD230 CAN Transceivers. It uses interrupts generated by the physical user button on the STM32 to generate random data/payload simulation, transmits this data to the Uno Q in which it is received, decoded and forwarded from the Uno Q's microcontroller to the Python microprocessor.

Python then sends the CAN frame information to a browser using WebSockets. A Javascript frontend displays both the decoded CAN fields and a reconstructed visualisation of the expected CANH/CANL dominant and recessive signal states.

Additionally, the Uno Q also transmits a response frame back to the STM32 upon receiving, demonstrating bidirectional CAN communication.

## Why I Built This

As mentioned, I built this in my process of learning Embedded Development. However, I also have a particular interest in automotive, and with CAN being one of the most dominant communication protocols used in automotive to communicate with electronic control units, I wanted to move beyond understanding the protocol theoretically and gain practical experience configuring CAN peripherals, transceivers, filters, interrupts, message transmission and reception.

Another motivation was that I did not have access to a CAN analyzer or oscilloscope. This led me to create my own browser-based visualisation of the CAN frames received. Note, the visualizer is not a replacement for an oscilloscope or physical signal analyzer, as it does not measure the electrical CANH/CANL signals.

Hardware:
- STM32F446RE Nucleo
- Arduino Uno Q
- 2x SN65HVD230 3.3V CAN Transceivers
- 2x 120Ω (100Ω + 20Ω) CAN Termination resistors
- Breadboard
- Jumper wires (Including pair wires for CANH/CANL)

CAN Configuration:
| Parameter   | Config |
| -------- | ------- |
| Protocol  | Classic CAN    |
| Bit rate | 500kbit/s     |
| STM32 CAN Peripheral    | CAN1/bxCAN    |
| STM32 TX/RX    | PA12/PA11    |
| Uno Q TX/RX    | D4/D5    |
| ID format  | 11-bit    |
| STM32 ID    | 0x446    |
| Uno Q ID    | 0x101    |
| DLC    | 8 bytes    |

Both the STM32 and the Arduino Uno Q are setup with CAN receive filters - The STM32 will only accept the Uno Q's ID and vise versa.

## How It Works

- The STM32 initializes CAN1 in Classic mode at 500kbit/s.
- When pressed, the STM32's user button generates an external GPIO interrupt in which the STM32 generates a random CAN payload.
- The STM32 places the frame into a bxCAN transmit mailbox in which the messsage is then displayed via USART terminal.
- The SN65HVD230 converts the STM32 CAN TX/RX logic signals into the CANH/CANL bus.
- The Uno Q receives the CAN frame using its CAN controller.
- The Uno Q sends a response back to STM32.
- The STM32 receives the response through CAN RX FIFO0 and displays it via USART.
- The received values are converted into binary representations for visualisation and are then bridged from C++ (MCU) to Python (MPU).
- Python emits the frame to the browser using a WebSocket.
- Javascript updates the UI and constructs a visual representation of the expected CANH/CANL states (Up to the CAN frame's data).


## Design Decisions
- Used a 3.3V CAN Transceiver instead of the ordinary 5V Transceiver - In order to be compatible with the Arduino Uno Q, as the CAN-capable pins are not 5V tolerant.
- Interrupt-driven STM32 transmission - To demonstrate GPIO interrupt handling without continuously polling.
- WebSockets - To transmit the CAN data from the MPU to the browser.
- Reconstructed Waveform - Because no oscilloscope or CAN analyzer was available, the frontend reconstructs the expected logical CANH/CANL states from the decoded frame.
